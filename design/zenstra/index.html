Zenstra enterprise design direction

How Zenstra's website and console should look and behave so that a CISO, a security architect and an analyst each trust it, understand it, and can operate it. Nothing here is implemented in production code yet.

Evidence labels: Verified seen on zenstra.ai on 8 Oct 2026 · Inferred reasoned from evidence · Hypothesis proposed, not a current capability

00Read this first

Two findings change the brief. They matter more than any visual decision in this document.

1. The proof on the website does not survive a security review.

Verified The homepage shows 2 enterprise customers and 47+ protected agents next to six certification badges: ISO 27001, SOC 2 Type II, HIPAA, GDPR, ISO/IEC 42001 and ISO/IEC 27701:2025. HIPAA has no certification. The company address is a registered-agent service in Dover, Delaware, and there is no About, team or trust-center page.

Inferred A CISO reads that combination as a credibility gap and asks for the audit reports on the first call. If any badge is not backed by a current report or certificate, it is a misrepresentation risk, not a design problem. The redesign replaces badges with a trust table that states each item's real status. Confirm every claim before launch.

2. The category consolidated this year. Differentiation now beats polish.

Verified on competitor sites, 8 Oct 2026: Astrix is now part of Cisco and stopped standalone sales on 30 June 2026. Palo Alto Networks completed its acquisition of Portkey to secure AI agents. Zenity and Noma both cite Gartner "Market Shaper" recognition. Semperis and Tenable both lead their homepages with agentic AI. Zenstra's eight capability names are close to identical to theirs.

Inferred A better-looking horizontal "agentic AI security" site still loses to vendors with logos and analyst reports. The sharpest assets Zenstra already has are its credit-union page (NCUA, Fiserv agentOS, Jack Henry, Temenos) and its inline, before-execution enforcement story. The direction below leads with those.

01Product understanding

What Zenstra is

Verified A runtime security layer that sits inline between AI agents and the tools, APIs, MCP servers and systems of record they call. Each request passes identity, policy and threat checks before it executes. Deployed through an SDK (named "Khetaka" on the site), a proxy or gateway, and, on the credit-union page, a desktop app on employee devices.

Category: AI agent security, overlapping AI runtime protection (AI-DR), AI security posture management and identity for non-human actors. Inferred The closest direct competitors are Zenity, Noma, Aembit and Astrix (now Cisco); the closest platform threats are Palo Alto Networks and Microsoft.

What it protectsSystems of record (core banking, LOS, CRM, ERP), data and money that agents can reach through tools and credentials.
Problem it solvesAgents hold credentials, keep memory and take irreversible actions, often with no human in the loop. Existing controls see a valid token or an API call, not the decision that produced it.
Why it is hardAgents are non-deterministic; intent is only visible inside the loop; untrusted content (documents, web pages, member messages) can redirect them; enforcement must add almost no latency and must fail safely.
Without itShadow agents with standing access, no inventory for an examiner, prompt injection leading to data exfiltration, and no record of who or what decided an action.
Value propositionInventory every agent, decide every action before it lands, and prove what happened. In this document: Discover, Enforce, Prove.

Recommended positioning

For regulated financial institutions adopting AI agents, Zenstra is the runtime control that checks every agent action before it executes and records the decision as exam-ready evidence. Unlike posture and discovery tools, it stops the action; unlike AI firewalls, it decides on the action, not the text.

Horizontal messaging stays on the homepage; the credit-union and banking story is the lead solution until there are logos outside it.

03Competitive research

All three reference sites were rendered and read on 8 October 2026, along with four direct competitors. What follows is what each does and why it works, then what Zenstra should take and leave.

Semperis

Structure

  • Nav: Why Semperis, Platform, Solutions, Services, Resources, Partners, Company; red "Request a demo".
  • Utility bar with a red "Experiencing a breach?" link: a crisis entry path for a buyer under attack.
  • Hero names the category first ("The identity resilience platform"), then a claim, then two CTAs.
  • Capabilities organised by time: pre-attack, during, post-attack.
  • Free assessment tool (Purple Knight) as top-of-funnel proof; named ex-CISO quote; community; documentary.

Why it reads as enterprise

  • Scale proof ("150+ million identities protected") with a decade of history.
  • Square buttons, monospace uppercase eyebrows, dark photographic hero: serious, not playful.
  • The lifecycle frame maps to how a security programme is organised, so the buyer can place the product.
  • Take: lifecycle grouping, crisis path, a free assessment tool. Leave: video hero, crowded utility bar.

Tenable

Structure

  • Skip links to navigation, content and footer before anything else.
  • Nav includes Pricing; header actions Buy and Try; product login in the utility menu.
  • One platform (Tenable One) explained through exposure domains: AI, cloud, OT, identity, vulnerability.
  • Analyst recognition (Gartner, IDC) and Peer Insights after the product, not before it.

Why it reads as enterprise

  • Transactional paths for every buyer stage: read, try, buy, sign in.
  • One loud brand colour used only on actions; everything else neutral.
  • A single platform with modules scales as products are added.
  • Take: skip links, sign-in in the header, domain-based architecture, restrained accent. Leave: rotating announcement carousel.

Palo Alto Networks

Structure

  • Mega navigation: Products, Solutions, Services, Industries, Partners, Resources; "Demos and Trials".
  • Hero, then a recommended-content strip of analyst reports and launches.
  • Live telemetry with a timestamp ("Daily data as of 10.8.26": attacks prevented inline, unique objects analysed).
  • Platformisation narrative; solutions by outcome ("Secure your AI ecosystem") and by industry.

Why it reads as enterprise

  • Timestamped numbers feel measured rather than claimed.
  • Industries as a top-level path: buyers navigate by who they are.
  • Take: timestamped, sourced numbers (for Zenstra: technical specs, not volumes); industry paths. Leave: stock photography, density of competing CTAs, cookie and banner clutter.

Patterns adopted

  1. Category in the first three words of the hero (Semperis).
  2. Lifecycle grouping of capabilities: Discover, Enforce, Prove (Semperis, Astrix).
  3. Sign in and Request a demo always in the header; Docs in Resources (Tenable, Aembit).
  4. Industry as a first-class path, credit unions first (Palo Alto Networks).
  5. Mechanism before benefit for architects: sequence diagram and spec sheet (Aembit, Cloudflare).
  6. Trust center with per-item status instead of a badge wall.
  7. Skip links and semantic landmarks (Tenable).

Component and motion references

  • shadcn/ui: the useful part is its architecture: accessible primitives (Radix) copied into the codebase and styled with CSS variables. Use it as the pattern for Zenstra's own component package: own the code, keep the accessibility of the primitives, theme through tokens.
  • Motion (motion.dev): use it for layout transitions, drawers and list reordering with critically damped springs.
  • Anime.js: timeline sequencing for one explanatory SVG at a time (the architecture sequence on the marketing site). Not for interface movement.
  • bklit: chart behaviour worth adopting: grow from the baseline, hover dims the others, skeletons that respect reduced motion.

05Design strategy

Principles

  1. Show the decision, not the dashboard. Zenstra's unit of work is a decision: agent, action, policy, verdict, latency. Every surface, from the homepage hero to the console, is built from it.
  2. Prove before you claim. Each claim links to a mechanism, a spec, a document or a status. Remove what cannot be backed.
  3. One thing leads. Every screen answers one question first; the rest supports it.
  4. Colour means state. Neutrals carry the layout. Red, amber and green appear only for severity and verdicts, always with a shape and a word.
  5. Built for the second reader. The CISO forwards the page to an architect; the analyst escalates to a lead. Each page holds up for the reader it gets forwarded to.

Visual direction

Two surfaces, one system. The marketing site uses the brand's deep navy as a band for the hero, product tour and CTA, with light content sections between them, so the product preview reads as a real console inside the page. The console is light-first with a full dark theme, dense, bordered rather than shadowed, with monospace reserved for identifiers, policy and timestamps. Left-aligned text, square-ish corners (6–8px), no glassmorphism, no glow, no gradient text. The only gradient left is in the logo mark.

Signature elements

  • The decision ledger as the hero image and the console's audit view.
  • Verdict glyphs: open circle for Allow, triangle for Step-up, filled square for Block. Distinct by shape, so they survive colour blindness and greyscale print.
  • The run timeline: millisecond timestamps, one row per agent step, with the evidence inline.

Component strategy

Build one Zenstra component package. Underneath, use Radix primitives for dialog, popover, menu, tabs and tooltip to get focus management and ARIA right. Publish tokens once and consume them in both apps. New components are added only when two screens need them.

Data visualisation

  • Prefer a number with a comparison over a chart. Charts appear only for trends and comparisons.
  • Single series by default in brand blue; a reference line (average, threshold) in muted dashes.
  • Never colour bars by rank; red only marks a value below a stated threshold, and the threshold is written under the chart.
  • Every chart has a text alternative and a hover readout; time axes label real dates.

08Motion

Motion explains a change of state. If removing an animation loses no information, remove it.

MomentMotionWhy
New ledger entryRow slides 6px and fades in, brief cyan wash; 320ms ease-outShows that decisions are happening now, without a counter ticking up

Rules: nothing over 400ms in the console; no parallax; no scroll-jacking; anything that moves for more than 5 seconds has a pause control; everything is removed under prefers-reduced-motion.

Phones are for reading and approving: an executive opening a forwarded investigation, or an approver handling a Step-up. Design those two flows for phones first; everything else degrades gracefully.

Accessibility

  • Target: WCAG 2.2 AA on both themes. Muted text meets 4.5:1 on its surface.
  • Never colour alone: severity chips carry words; verdicts carry shapes and words; charts carry labels.
  • Keyboard: skip link, visible focus ring (cyan, 2px offset), Ctrl/Cmd K, J/K in lists, Esc closes overlays, focus returns to the trigger.
  • Semantics: landmarks (header, nav, main), real tables with scoped headers, dialogs with aria-modal, live regions for the brief and toasts.
  • Charts: role="img" with a description of the trend, plus a table view.
  • Forms: visible labels, errors that say how to fix, no placeholder-only fields.
  • Motion: reduced-motion honoured everywhere; the live ledger has a pause button.

11Implementation plan

The current marketing site is a client-rendered Vite build. The plan below is a target architecture for Zenstra, to be checked against Zenstra's real codebase before work starts.

Recommended architecture

zenstra-web/ one repository for both front ends apps/site marketing site, statically generated (Astro or Next.js static export) apps/console React + Vite single-page app behind sign-in packages/tokens zx.css as the single source for colour, type, spacing, motion packages/ui Zenstra components on Radix primitives packages/icons one icon set (lucide) with the verdict glyphs added
  • Static generation for the site fixes the empty-HTML problem: content is in the page for crawlers, link previews and screen readers before JavaScript runs.
  • The console stays a SPA. It is behind sign-in, so SEO does not matter there.
  • One animation library per job: Motion for interface movement, anime.js only for explanatory SVG timelines, CSS for the rest.
  • Hand-built SVG charts. There are few of them; a small component per chart type keeps bundle size down and follows the motion rules.

12Decisions needed

  1. Which certifications and numbers are real today? For each badge: certificate or report, auditor, date. Anything without one comes off the site.
  2. Vertical or horizontal lead? Recommended: credit unions and regulated financial institutions as the lead solution, horizontal homepage behind it.
  3. What is the SDK called? "Khetaka" or "Zenstra SDK". One name across site, docs and console.
  4. Which deployment modes ship today? SDK, gateway, endpoint app: confirm each, with tested frameworks.
  5. Who is on the About page? Named founders and engineers do more for trust at this stage than any badge.
