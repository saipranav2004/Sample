The risk

An agent is a privileged user nobody interviewed.

Agents hold credentials, keep memory and take actions that cannot be undone. Network controls see an API call. Identity providers see a valid token. Neither sees the decision that led to it.

FirewallsSee traffic, not intent
Identity providersIssue a token, then step aside
AI filtersScreen text, not actions

FAQ

Questions security architects ask first.

What happens to agent traffic if Zenstra is unavailable?

Each agent and tool has a fail mode. The default is fail-closed: the action is held and the agent receives a refusal it can handle. You can set specific low-risk tools to fail-open, and every fail-open decision is still recorded once the decision point recovers.

Does Zenstra see or store our prompts and data?

The decision point runs in your environment. Prompt and tool payloads are evaluated there. The ledger stores decisions and redacted evidence by default, and full payload retention is a per-agent setting you control.

How much latency does inspection add?

Policy checks are evaluated locally. The published methodology lists the load, policy count and hardware behind the latency figures, so your team can reproduce them.

Which frameworks, models and protocols do you support?

Any framework through the SDK or gateway, including MCP and agent-to-agent traffic. The integrations page lists tested versions.

How is this different from an AI firewall or an identity provider?

An AI firewall filters text. An identity provider issues tokens. Zenstra decides whether a specific agent may take a specific action for a specific task, at the moment it tries, and records why.
