Decide every actionbefore it lands.

Policy is evaluated in the agent loop, on every tool call, in your environment. Zenstra allows the call, holds it for a person, or blocks it, and the tool never sees a blocked request.

Request a demo Read a policy
policies/member-data-egress.zplv7 · active
# POL-114 · owner: Information Security
policy member-data-egress {
  when tool == "email.send"
   and payload.contains(class: "member.account")
   and recipient.domain not in approved_domains
  then block, notify("#sec-agents")
}

Three verdicts, decided in milliseconds.

Every decision carries the policy version, the evidence and the agent's declared task, so it can be explained later.

Allow

Within policy and within the task

The call continues with a scoped grant that expires with the call or the session.

Secure tool access

Scoped, expiring grants instead of standing credentials.

Each agent receives only the tools its job needs, scoped to the data it should touch, for as long as the call or session lasts. The secrets themselves stay in the Context Vault and never reach the model.

  • Grants scoped per tool, per collection, per member
  • Unused grants flagged so the blast radius keeps shrinking
  • Every MCP connector into core, LOS or CRM becomes a reviewed grant
Prompt injection defense

Untrusted content never steers the agent.

Retrieved documents, web pages and member messages are screened before the agent plans. Injected instructions are quarantined, and the agent's intended action is checked against the task it declared.

  • Direct and indirect injection, mapped to MITRE ATLAS AML.T0051
  • Intent verification: declared task against the actual tool call
  • The full run, with the injected span, kept for the investigation
Memory protection

Signed memory, so poison does not persist.

Every write to long-term memory is signed by the agent's key and carries its provenance. Unsigned or out-of-pattern writes are rejected, and a jump in memory writes shows up against the agent's baseline.

  • Provenance on every memory entry
  • Cross-session contamination blocked between member and staff assistants
Policy as code

Write a guardrail once, enforce it everywhere.

Policies are versioned files reviewed like any other change. The same policy applies whatever the model, framework or deployment mode, and every decision records the version that made it.

  • Review, test and simulate a policy against last week's decisions before it goes live
  • Owners per policy, with change history in the ledger
  • Your acceptable-use policy, enforced instead of remembered

Approvals and emergency stop

A person decides the risky calls.

Step-up verdicts go to a named approver with the plan attached. If something goes wrong, emergency stop halts one agent, one tool or the whole environment, with a reason recorded in the ledger.

  • Approvers and separation of duties from your identity provider
  • Stops scoped to the narrowest blast radius first
  • Typed confirmation, so it is never one accidental click
